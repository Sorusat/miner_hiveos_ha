# HiveOS Miner — кастомная интеграция для Home Assistant

Локальное управление ASIC-майнерами на HiveOS. Без облака, без HACS, без токенов:
интеграция стучится напрямую в локальный веб-интерфейс HiveOS по HTTP digest auth.

## Как это работает

Майнер добавляется один раз через «Настройки → Устройства и службы → Добавить интеграцию →
HiveOS Miner»: вводится имя, IP-адрес, логин и пароль. Дальше добавляешь 10.0.1.112 и
10.0.1.116 точно так же — общий код при этом не дублируется, это разные config entry.

## Установка

Скопировать папку `custom_components/hiveos_miner` в `config/custom_components/`
(в HA OS / Supervised это `/config/custom_components/`), затем перезагрузить Home Assistant.
В HA Core на Windows/MacOS — перезапустить.

## Эндпойнты

Все требуют digest-аутентификацию (`root:root` по умолчанию):

```
GET /cgi-bin/get_miner_status.cgi   статус (JSON)
GET /cgi-bin/start_miner.cgi        запуск
GET /cgi-bin/stop_miner.cgi         остановка
GET /cgi-bin/resume_miner.cgi       продолжить с паузы
TCP  :4028 {"command":"get_log"}    лог bmminer (только чтение)
```

Лог по TCP используется для различения «приостановлен» и «остановлен»: при нулевом
хэшрейте эти два состояния по JSON неразличимы. Отказ чтения лога не считается ошибкой —
состояние просто определяется по хэшрейту.

## Сущности на каждый майнер

| Тип | Имя | Назначение |
|---|---|---|
| switch | Майнинг | вкл/выкл, работает в автоматиках |
| binary_sensor | Доступен | связь с устройством |
| binary_sensor | Майнит | фактический майнинг |
| sensor | Состояние | Майнинг / Запуск / Приостановлен / Остановлен |
| sensor | Хэшрейт | GH/s, 5-секундный |
| sensor | Средний хэшрейт | GH/s, по аптайму |
| sensor | Температура | максимум по платам и чипам |
| sensor | Потребление | Вт, из total_power |
| sensor | Время работы | минуты |
| sensor | Принятые / Отклонённые шары | счётчики |
| sensor | Платы | сколько плат с ненулевой температурой |
| sensor | Пулы | статус и адреса пулов |

## Автоматизация

Расписание по тарифу и излишкам СЭС делается автоматиками HA, а не на стороне HiveOS —
иначе теряется связь с датчиком мощности. Обязателен защитный слой: если HA лёг,
майнеры останутся в последнем состоянии. Это лечится watchdog-автоматикой, которая
при пропадании HA переводит их по тарифному окну.

Гистерезис и минимальный интервал между переключениями (15–20 минут) — тоже на стороне HA,
иначе колебания выработки СЭС будут дёргать майнеры постоянно.

## Отладка

Состояние и сырые значения видны в Developer Tools → States. При проблемах с авторизацией
проверить вручную:

```bash
curl -s --digest -u root:root http://10.0.1.114/cgi-bin/get_miner_status.cgi
```

Без `--digest` сервер вернёт 401 — это ожидаемо.
