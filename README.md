# HiveOS Miner — кастомная интеграция для Home Assistant

Локальное управление ASIC-майнерами на HiveOS. Без облака, без токенов: интеграция
стучится напрямую в локальный веб-интерфейс HiveOS по HTTP digest auth.

Требуется Home Assistant 2025.7 или новее (aiohttp с DigestAuthMiddleware).
Адрес можно вводить как `192.168.1.192`, `miner.local:8080` или
`http://miner.local:8080/`. TCP-лог использует отдельный порт 4028.

Интеграция универсальная: IP, модель, учётные данные и интервал опроса вводятся
при добавлении, ничего не зашито в код.

Список изменений по версиям — в [CHANGELOG.md](CHANGELOG.md).

## Как это работает

Майнер добавляется один раз через «Настройки → Устройства и службы → Добавить интеграцию →
HiveOS Miner»: вводится имя, IP-адрес, модель, логин и пароль. Каждый следующий майнер
добавляется точно так же — общий код при этом не дублируется, это разные config entry.
Никаких скриптов копировать не нужно.

## Установка

### Через HACS (рекомендуется)

«Настройки HACS → Репозитории → Добавить» → вставить
`https://github.com/Sorusat/miner_hiveos_ha` → выбрать категорию «Интеграции» →
«Магазин» → HiveOS Miner → Установить → Перезагрузить Home Assistant.

Дальше обновления приходят кнопкой в HACS, файлы руками переносить не нужно.

Если HACS ещё не установлен, он берётся как аддон в Supervisor (HA OS / Supervised)
или через контейнер `ghcr.io/hacs/integration`.

### Вариант 2: git на машине Home Assistant

Клонировать репозиторий и связать его симлинком — файлы не копируются, обновление
одной командой:

```bash
cd ~/.config                                   # каталог конфигурации HA
git clone https://github.com/Sorusat/miner_hiveos_ha.git
mkdir -p custom_components
ln -s ~/.config/miner_hiveos_ha/custom_components/hiveos_miner \
       ~/.config/custom_components/hiveos_miner
```

Если HA в Docker, клон делай на хосте, а в контейнере монтируй каталог `config`.

Обновление после этого:

```bash
cd ~/.config/miner_hiveos_ha && git pull
```

и перезагрузка Home Assistant. Симлинк сам подхватит изменения.

### Вариант 3: просто скопировать папку

Скопировать `custom_components/hiveos_miner` в `config/custom_components/`
(в HA OS / Supervised это `/config/custom_components/`), затем перезагрузить Home Assistant.
В HA Core на Windows/macOS — перезапустить.

## Настройка

Все параметры вводятся при добавлении майнера, ничего не зашито в код:

| Поле | Назначение |
|---|---|
| Название | имя устройства в интерфейсе |
| IP-адрес | адрес майнера в локальной сети |
| Модель | отображается в карточке устройства |
| Логин / Пароль | учётные данные веб-интерфейса HiveOS |
| Интервал опроса | как часто забирать состояние, по умолчанию 30 секунд |

При смене пароля на самом майнере Home Assistant сам запросит новые данные — интеграция
поддерживает reauth. Любые параметры можно поменять и на устройстве через «Настроить»,
майнер при этом не удаляется, а проверяется на связь перед сохранением.

## Эндпойнты

Все требуют digest-аутентификацию (по умолчанию `root:root`, задаётся при настройке):

```
GET /cgi-bin/get_miner_status.cgi   статус (JSON)
GET /cgi-bin/stop_miner.cgi         приостановить майнинг (без отключения питания)
GET /cgi-bin/resume_miner.cgi       запустить майнинг или продолжить с паузы
TCP  :4028 {"command":"get_log"}    лог bmminer (только чтение)
```

Таймауты: 10 секунд на HTTP-запрос, по 5 секунд на подключение и чтение лога.
Обесточенный майнер не отвечает вообще. При отсутствии ответа основной сенсор
показывает «Выключен», а числовые показатели становятся недоступными.

Положительный хэшрейт означает «Работает». Если майнер отвечает с нулевым
хэшрейтом и реальными пулами Disabled, он «Приостановлен»; TCP-лог для этого
не нужен. Лог используется как дополнительный сигнал запуска.

После `resume` нулевой статус временно отображается как «Запуск...». Защёлка
действует до появления хэшрейта или пяти минут. После её истечения отвечающий
майнер без признаков запуска отображается как «Приостановлен». «Выключен»
означает отсутствие сетевого ответа, а не нулевой хэшрейт.

## Сущности на каждый майнер

| Тип | Имя | Назначение |
|---|---|---|
| switch | Майнинг | запустить или приостановить майнер |
| sensor | Состояние | Работает / Запуск / Приостановлен / Выключен |
| sensor | Хэшрейт | GH/s, 5-секундный |
| sensor | Температура | максимум по платам и чипам |
| sensor | Потребление | Вт, из total_power |
| sensor | Время работы | дни, часы, минуты и секунды |
| sensor | Живых пулов | сколько пулов отвечает |

При отсутствии ответа основной сенсор показывает «Выключен», а числовые
показатели не содержат актуальных значений, счётчик живых пулов равен нулю.
Переключатель сохраняется, но команда resume работает только при доступном
HTTP-интерфейсе: она не включает физически обесточенный майнер. Для подачи
питания нужна отдельная управляемая розетка или контактор.

Живые пулы считаются только при положительном хэшрейте и явном статусе Alive.
Пустой статус пула считается неподтверждённым. Пауза с пулами Disabled
определяется по JSON даже после перезапуска интеграции. Отвечающий майнер
без хэшрейта и без признаков запуска отображается как «Приостановлен»;
состояние также может означать простой, поскольку отдельный режим ошибки
майнинга в текущем интерфейсе не предусмотрен.

Переключатель связан с устройством и наследует его пространство, если для
самой сущности не задано другое пространство. Home Assistant сохраняет
пользовательские имена (`Sw`) и идентификаторы (`switch.miner192`) при
обновлении. Их можно изменить в настройках сущности; старое имя ID само по
себе не означает управление другим майнером.

Файлы icon.png/icon.svg в репозитории — исходные изображения. Для появления
логотипа на странице интеграции требуется регистрация брендинга в
home-assistant/brands; добавление файлов в этот репозиторий этого не делает.

## Автоматизация

Расписание по тарифу и излишкам СЭС делается автоматиками HA, а не на стороне HiveOS —
иначе теряется связь с датчиком мощности. Обязателен защитный слой: если HA лёг,
майнеры останутся в последнем состоянии. Это лечится watchdog-автоматикой, которая
при пропадании HA переводит их по тарифному окну.

Гистерезис и минимальный интервал между переключениями (15–20 минут) — тоже на стороне HA,
иначе колебания выработки СЭС будут дёргать майнеры постоянно.

### Уведомление о недоступных пулах

Майнер, у которого все пулы мертвы, продолжает считать в пустоту: хэшрейт есть,
а шары не принимаются. Числовой датчик «Живых пулов» становится равен 0.

Триггер: числовой датчик «Живых пулов» переходит в 0.
Условие: майнер при этом в состоянии «Работает» или «Запуск».
Действие: отправить сообщение в Telegram через `notify.mobile_app_*`.

Для автоматизации следует дополнительно проверять состояние «Работает», чтобы
выключенный майнер не воспринимался как авария пулов.

## Версии

Релизы помечаются тегами `vX.Y.Z`, они же показываются в HACS как версия интеграции.
Версия в `manifest.json` обязана совпадать с последним тегом.

Хэши коммитов вроде `dd84474` — это контрольные суммы содержимого, они вычисляются
сами и задать их нельзя. Читаемое имя релиз получает через тег.

При выпуске новой версии порядок такой:

1. Обновить `version` в `custom_components/hiveos_miner/manifest.json`.
2. Добавить раздел в `CHANGELOG.md` с датой и списком изменений.
3. Закоммитить, пометить тегом `git tag -a vX.Y.Z -m "..."`, отправить
   вместе с тегами: `git push origin main --follow-tags`.

## Тесты

Тесты гоняются без Home Assistant: `api.py` загружается напрямую с диска, а вместо
майнера поднимается локальный сервер с настоящей digest-защитой.

```bash
python -m pip install aiohttp
python tests/test_api.py
python -m pip install voluptuous
python tests/test_review.py
```

Проверяется всё, что ломается тихо: digest-аутентификация, разбор статуса, команды
start/stop/resume, отказ при неверном пароле, быстрый отказ на недоступном майнере
и матрица состояний. Именно такой тест поймал ошибку с аутентификацией в первом
релизе — она не проявлялась нигде, кроме формы добавления.

## Отладка

Состояние и сырые значения видны в Developer Tools → States. При проблемах с авторизацией
проверить вручную:

```bash
curl -s --digest -u <логин>:<пароль> http://<ip-майнера>/cgi-bin/get_miner_status.cgi
```

Без `--digest` сервер вернёт 401 — это ожидаемо.
